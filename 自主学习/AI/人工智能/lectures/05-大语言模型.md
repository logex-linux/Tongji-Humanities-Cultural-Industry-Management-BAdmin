## 一、LLM 是什么？

### 1.1 本质：下一个词预测器

大语言模型的核心任务极其简单——**给定前文，预测下一个最可能的词（token）**：

$$P(x_{t+1} | x_1, x_2, ..., x_t)$$

```
输入: "今天天气真"
模型输出概率分布:
  "好"  → 0.45
  "不错" → 0.20
  "热"  → 0.15
  "冷"  → 0.08
  ...
```

就这么简单的任务，当模型足够大、数据足够多时，涌现出了翻译、推理、编程、创作等能力。

### 1.2 规模：从百万到万亿参数

| 模型 | 年份 | 参数量 | 训练数据 |
|------|------|--------|----------|
| GPT-1 | 2018 | 1.17 亿 | BookCorpus (7000本书) |
| GPT-2 | 2019 | 15 亿 | WebText (40GB) |
| GPT-3 | 2020 | 1750 亿 | 570GB 混合文本 |
| LLaMA-2 | 2023 | 7B-70B | 2TB token |
| GPT-4 | 2023 | ~1.8万亿 (MoE) | 未公开 |
| Qwen-2.5 | 2024 | 0.5B-72B | 多语言大规模语料 |
| DeepSeek-V3 | 2025 | 671B (MoE) | 14.8T token |

### 1.3 Scaling Laws（缩放定律）

Kaplan et al. (2020) 和 Chinchilla (2022) 发现：

$$L(N, D, C) \approx \left(\frac{N_c}{N}\right)^{\alpha_N} + \left(\frac{D_c}{D}\right)^{\alpha_D} + L_\infty$$

- N = 参数量，D = 数据量，C = 计算量
- 模型性能随三者**幂律**提升，没有明显上限
- **Chinchilla 最优**：参数量和数据量应等比例增长（20 token/参数）

**实践意义：**
- 7B 模型需要 ~140B token 训练
- 70B 模型需要 ~1.4T token 训练
- 不是越大越好，要平衡参数和数据

## 二、LLM 训练全流程

### 2.1 三阶段训练

```
阶段1: 预训练 (Pre-training)
  数据: 海量无标注文本 (TB级)
  目标: 下一个 token 预测
  算力: 数千 GPU × 数月
  结果: 基座模型 (Base Model)

阶段2: 监督微调 (SFT - Supervised Fine-Tuning)
  数据: 高质量指令-回答对 (万~十万条)
  目标: 学会遵循指令、对话格式
  结果: 指令模型 (Instruct Model)

阶段3: 对齐 (Alignment)
  方法: RLHF / DPO
  目标: 让回答有帮助、诚实、无害
  结果: 对齐后的模型 (Chat Model)
```

### 2.2 预训练细节

**数据准备：**
```
原始网页 → 去重 → 质量过滤 → 有害内容过滤 → 混合配比
                                                    ↓
                                          代码 15%
                                          书籍 10%
                                          维基百科 5%
                                          网页 60%
                                          学术论文 5%
                                          对话 5%
```

**训练配置（以 7B 模型为例）：**
```python
config = {
    "model": {
        "hidden_size": 4096,
        "num_layers": 32,
        "num_heads": 32,
        "vocab_size": 32000,
        "max_seq_len": 4096,
    },
    "training": {
        "batch_size": 4_000_000,  # token 数
        "learning_rate": 3e-4,
        "warmup_steps": 2000,
        "total_steps": 500_000,
        "optimizer": "AdamW",
        "precision": "bf16",
    }
}
```

**分布式训练：**
- 数据并行 (DP)：每个 GPU 处理不同数据
- 张量并行 (TP)：一层切分到多个 GPU
- 流水线并行 (PP)：不同层在不同 GPU
- ZeRO (DeepSpeed)：优化器状态/梯度/参数分片

### 2.3 Tokenizer：BPE 详解

```python
# BPE 训练过程（简化）
# 初始：每个字符是一个 token
# 统计所有相邻 token 对的频率
# 合并最频繁的对
# 重复直到达到目标词表大小

# 例：
# "low low low lowest"
# 初始: ['l','o','w',' ','l','o','w',' ','l','o','w','e','s','t']
# 第1轮合并: 'lo' (出现3次) → ['lo','w',' ','lo','w',' ','lo','w','e','s','t']
# 第2轮合并: 'low' (出现3次) → ['low',' ','low',' ','low','e','s','t']
# ...

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
print(tok.tokenize("Hello, world!"))  # ['▁Hello', ',', '▁world', '!']
print(tok.vocab_size)  # 32000
```

## 三、对齐技术：让 AI "听话"

### 3.1 为什么需要对齐？

预训练模型只会"续写"，不会"回答问题"：

```
用户: "中国的首都是哪里？"
Base Model: "中国的首都是哪里？这是一个常见的地理知识问题。
            在考试中，这类题目通常出现在..."（继续写文章）

Chat Model: "中国的首都是北京。"（直接回答）
```

### 3.2 SFT（监督微调）

用高质量的"指令-回答"对训练：

```json
[
  {
    "instruction": "解释什么是光合作用",
    "output": "光合作用是植物利用阳光、水和二氧化碳制造葡萄糖和氧气的过程..."
  },
  {
    "instruction": "写一首关于春天的诗",
    "output": "春风拂面柳丝长，桃花灼灼映斜阳..."
  }
]
```

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model
import torch

# 加载基座模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf")
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")

# 格式化训练数据
def format_example(instruction, output):
    return f"[INST] {instruction} [/INST] {output}"

# SFT 训练（通常用 LoRA 节省显存）
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: 4M || all params: 6.7B || 0.06%
```

### 3.3 RLHF（基于人类反馈的强化学习）

```
步骤1: 训练奖励模型 (Reward Model)
  给模型同一个问题，生成多个回答
  人类标注员排序：回答A > 回答B > 回答C
  训练一个奖励模型来预测人类偏好

步骤2: PPO 强化学习
  用奖励模型的分数作为奖励信号
  用 PPO 算法优化语言模型的策略
  同时加 KL 散度约束，防止模型偏离太远
```

$$\text{reward} = R(x, y) - \beta \cdot D_{KL}(\pi_\theta \| \pi_{ref})$$

### 3.4 DPO（直接偏好优化）

DPO 跳过了奖励模型，直接用偏好数据优化：

$$\mathcal{L}_{DPO} = -\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)$$

- $y_w$：人类偏好的回答（winner）
- $y_l$：人类不偏好的回答（loser）

**DPO vs RLHF：**
- DPO 更简单（不需要训练奖励模型、不需要 PPO）
- 训练更稳定
- 效果接近 RLHF
- 当前主流方案

## 四、Prompt Engineering

### 4.1 基本原则

```
好的 Prompt = 角色 + 任务 + 约束 + 格式 + 示例
```

```python

"帮我写代码"

# 好的 prompt
"""
你是一位资深 Python 工程师。请帮我写一个函数，要求：
- 功能：读取 CSV 文件，计算每列的均值和标准差
- 输入：文件路径（字符串）
- 输出：字典 {列名: {"mean": 值, "std": 值}}
- 要求：处理缺失值（跳过 NaN），添加类型注解和 docstring
- 风格：简洁，用 pandas 实现
"""
```

### 4.2 高级技巧

**Few-shot（少样本示例）：**
```
将以下句子分类为"正面"或"负面"：

"这家餐厅太棒了！" → 正面
"等了一个小时才上菜" → 负面
"味道一般般吧" → 负面
"环境优雅，服务周到" → 正面
"性价比很低，不推荐" →
```

**Chain-of-Thought（思维链）：**
```
问题：一个商店打八折后再减20元，原价200元的商品最终多少钱？

让我们一步步思考：
1. 原价：200元
2. 打八折：200 × 0.8 = 160元
3. 再减20元：160 - 20 = 140元
答案：140元
```

**ReAct（推理+行动）：**
```
问题：2024年诺贝尔物理学奖得主是谁？

思考：我需要查找2024年诺贝尔物理学奖的信息
行动：搜索 "2024 Nobel Prize Physics"
观察：John Hopfield 和 Geoffrey Hinton 因神经网络基础研究获奖
思考：我已经得到了答案
回答：2024年诺贝尔物理学奖授予了 John Hopfield 和 Geoffrey Hinton
```

### 4.4 温度与采样策略

# 温度 (temperature)：控制随机性
# T=0: 贪心（总是选概率最高的词）→ 确定性、重复

# Top-k：只从概率最高的 k 个词中采样

response = client.chat.completions.create(
    model="gpt-4",
    messages=[...],
    temperature=0.7,   # 创造性任务用 0.7-1.0
    top_p=0.9,
    max_tokens=1000,
)

## 五、微调实践

### 5.1 LoRA / QLoRA 原理

**全量微调的问题：** 7B 模型需要 ~60GB 显存（仅参数），加上梯度和优化器状态需要 ~120GB。

**LoRA 的思想：** 不直接修改原始权重 W，而是学习一个低秩增量：

$$W' = W + \Delta W = W + BA$$

其中 B ∈ ℝ^(d×r)，A ∈ ℝ^(r×d)，r << d（如 r=16, d=4096）

```
原始权重 W: 4096 × 4096 = 16M 参数（冻结）
LoRA 增量:  4096 × 16 + 16 × 4096 = 131K 参数（训练）
节省: 99.2% 的可训练参数！
```

### 5.2 用 Unsloth 快速微调

```python
from unsloth import FastLanguageModel
from datasets import load_dataset
from trl import SFTTrainer
from transformers import TrainingArguments

# 1. 加载模型（4-bit 量化）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Qwen2.5-7B-Instruct-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,
)

# 2. 添加 LoRA 适配器
model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0,
)

# 3. 准备数据
dataset = load_dataset("tatsu-lab/alpaca", split="train")

def format_prompt(example):
    return f"""### Instruction:
{example['instruction']}

### Response:
{example['output']}"""

# 4. 训练
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    args=TrainingArguments(
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        num_train_epochs=1,
        learning_rate=2e-4,
        fp16=True,
        output_dir="outputs",
    ),
)
trainer.train()

# 5. 保存（可以只保存 LoRA 权重，几十 MB）
model.save_pretrained("my_lora_adapter")
```

## 六、推理优化

### 6.1 KV Cache

自回归生成时，每生成一个新 token 都要重新计算注意力。KV Cache 缓存已计算的 Key 和 Value：

```
无 KV Cache: 生成第 n 个 token 需要计算 n 次注意力 → O(n²)
有 KV Cache: 只计算新 token 的 Q，复用缓存的 K,V → O(n)
```

```python
# HuggingFace 自动使用 KV Cache
outputs = model.generate(
    input_ids,
    max_new_tokens=100,
    use_cache=True,  # 默认开启
)
```

### 6.2 量化

减少每个参数的位数，大幅降低显存和加速推理：

| 精度 | 每参数位数 | 7B模型显存 | 质量损失 |
|------|-----------|-----------|----------|
| FP32 | 32 bit | ~28 GB | 无 |
| FP16/BF16 | 16 bit | ~14 GB | 极小 |
| INT8 | 8 bit | ~7 GB | 很小 |
| INT4 (GPTQ/AWQ) | 4 bit | ~3.5 GB | 轻微 |

```python
# 4-bit 量化加载
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)
model = AutoModelForCausalLM.from_pretrained(
    "model_name", quantization_config=bnb_config
)
```

### 6.4 投机解码 (Speculative Decoding)

```
传统自回归: 大模型逐 token 生成 → 慢
投机解码:
  1. 小模型快速生成 k 个候选 token
  2. 大模型一次性验证这 k 个 token
  3. 接受正确的，拒绝错误的，从错误处重新生成
  → 加速 2-3x，输出质量完全一致
```
