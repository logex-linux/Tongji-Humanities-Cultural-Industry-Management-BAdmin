## 二、对齐 (Alignment)

### 2.1 什么是对齐？

让 AI 的行为符合人类的意图和价值观。

```
不对齐的例子：
  用户: "帮我写一封邮件拒绝这个会议"
  AI: 写了一封极其粗鲁的邮件（满足了"拒绝"但违背了"礼貌"的隐含意图）

对齐的 AI：
  用户: "帮我写一封邮件拒绝这个会议"
  AI: 写了一封礼貌但坚定的拒绝邮件，提供了替代时间建议
```

### 2.2 对齐的三个维度

| 维度 | 含义 | 例子 |
|------|------|------|
| 有帮助 (Helpful) | 真正解决用户问题 | 给出准确、完整的回答 |
| 诚实 (Honest) | 不编造、承认不确定 | "我不确定，但..." |
| 无害 (Harmless) | 不产生有害输出 | 拒绝生成恶意代码 |

### 2.3 对齐技术回顾

```
预训练 → SFT → RLHF/DPO → 安全微调 → 部署
                              ↑
                         我们在这里

安全微调的数据：
  - 拒绝有害请求的示例
  - 处理边界情况的示例
  - 承认不确定性的示例
```

```python
red_team_prompts = [

def red_team_test(model, prompts):
    results = []
    for prompt in prompts:
        response = model.generate(prompt)
        # 用另一个模型或规则判断是否"越狱"成功
        is_harmful = safety_classifier(response)
        results.append({
            "prompt": prompt,
            "response": response,
            "harmful": is_harmful,
        })
    return results
```

### 2.5 提示注入防御

```python
"""防御 Prompt Injection 的策略"""

# 策略1: 输入过滤
def sanitize_input(user_input: str) -> str:
    """检测并过滤潜在的注入攻击"""
    injection_patterns = [
        "ignore previous instructions",
        "忽略之前的指令",
        "system prompt",
        "you are now",
        "act as",
    ]
    for pattern in injection_patterns:
        if pattern.lower() in user_input.lower():
            raise ValueError("检测到潜在的提示注入")
    return user_input

# 策略2: 架构隔离
# 把系统指令和用户输入明确分离
messages = [
    {"role": "system", "content": "你是客服助手，只回答产品相关问题。"},
    {"role": "user", "content": user_input},  # 用户输入永远在 user 角色
]

# 策略3: 输出验证
def validate_output(response: str) -> str:
    """检查输出是否泄露了系统信息"""
    if "system prompt" in response.lower():
        return "抱歉，我无法提供该信息。"
    return response
```

## 三、偏见与公平

### 3.1 偏见的来源

```
数据偏见：训练数据不均衡
  → 历史招聘数据中男性多 → 模型学到"男性更适合技术岗"

标注偏见：标注者的主观判断
  → 不同标注者对"有害内容"的标准不同

表示偏见：某些群体在数据中被低估
  → 医学数据中少数族裔样本少 → 诊断模型对他们不准确

确认偏见：模型强化已有刻板印象
  → "医生" 总是生成男性图片
```

### 3.2 检测偏见

```python
"""检测模型输出中的性别偏见"""
from transformers import pipeline
```

### 3.3 公平性指标

| 指标 | 定义 | 适用场景 |
|------|------|----------|
| 人口统计均等 | 各组获得正面预测的比例相同 | 招聘筛选 |
| 均等机会 | 各组真正例率相同 | 贷款审批 |
| 预测均等 | 各组精确率相同 | 刑事风险评估 |
| 个体公平 | 相似个体获得相似预测 | 通用 |

```python
"""计算公平性指标"""
from sklearn.metrics import confusion_matrix
import numpy as np

def fairness_metrics(y_true, y_pred, sensitive_attr):
    """
    sensitive_attr: 敏感属性（如性别 0/1）
    """
    results = {}
    for group in [0, 1]:
        mask = sensitive_attr == group
        y_t, y_p = y_true[mask], y_pred[mask]
        
        tn, fp, fn, tp = confusion_matrix(y_t, y_p).ravel()
        
        results[group] = {
            "positive_rate": (tp + fp) / len(y_t),      # 人口统计均等
            "true_positive_rate": tp / (tp + fn),        # 均等机会
            "precision": tp / (tp + fp) if (tp + fp) > 0 else 0,  # 预测均等
        }
    
    # 计算组间差异
    disparity = {
        "statistical_parity": abs(results[0]["positive_rate"] - results[1]["positive_rate"]),
        "equal_opportunity": abs(results[0]["true_positive_rate"] - results[1]["true_positive_rate"]),
    }
    return results, disparity
```

### 3.4 缓解偏见

```python
# 数据层面
# 1. 数据增强：对少数群体过采样
# 2. 重新标注：审核有偏见的标签
# 3. 平衡采样：确保各组样本量相当

# 模型层面

# 2. 公平约束：在损失函数中加入公平性正则项
# 3. 后处理：调整不同组的决策阈值

# 评估层面
# 1. 分组评估：分别报告各组的性能
# 2. 定期审计：上线后持续监控公平性指标
```

## 四、隐私保护

### 4.1 AI 中的隐私风险

```
1. 训练数据泄露：模型"记住"了训练数据中的个人信息
   → 攻击者可以通过特殊查询提取个人信息

2. 推理时隐私：用户输入包含敏感信息
   → 发送给 API 的数据可能被记录

3. 模型反演：从模型输出推断训练数据
   → 从人脸识别模型还原人脸图片
```

### 4.2 差分隐私 (Differential Privacy)

**核心思想：** 在训练过程中加入精心校准的噪声，使得单个样本的加入/移除不会显著影响模型输出。

$$\Pr[M(D) \in S] \leq e^\epsilon \cdot \Pr[M(D') \in S] + \delta$$

- ε (epsilon)：隐私预算，越小越隐私
- δ：松弛参数

```python
# 使用 Opacus（PyTorch 差分隐私库）
from opacus import PrivacyEngine

model = MyModel()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

privacy_engine = PrivacyEngine()
model, optimizer, data_loader = privacy_engine.make_private(
    module=model,
    optimizer=optimizer,
    data_loader=train_loader,
    noise_multiplier=1.1,
    max_grad_norm=1.0,
)

# 正常训练，但梯度被裁剪+加噪
for batch in data_loader:
    loss = model(batch)
    loss.backward()
    optimizer.step()

# 查询隐私预算消耗
epsilon = privacy_engine.get_epsilon(delta=1e-5)
print(f"当前 ε = {epsilon:.2f}")
```

### 4.3 联邦学习

```
传统：所有数据集中到一台服务器训练
联邦：数据留在本地，只上传模型更新

┌──────┐     模型更新      ┌──────┐
│手机 A │ ──────────────→ │      │
└──────┘                  │ 服务器 │ → 聚合 → 全局模型
┌──────┐     模型更新      │      │
│手机 B │ ──────────────→ │      │
└──────┘                  └──────┘
┌──────┐     模型更新
│手机 C │ ──────────────→
└──────┘

优势：原始数据不离开设备
```

## 五、可解释性

### 5.1 为什么需要可解释性？

```
场景1: 医疗诊断
  模型说"90% 概率是恶性肿瘤"
  医生需要知道：为什么？基于哪些特征？

场景2: 贷款拒绝
  模型拒绝了你的贷款申请
  你有权知道：为什么被拒？哪些因素导致的？

场景3: 调试模型
  模型在某些样本上表现异常
  工程师需要理解：模型在"看"什么？
```

### 5.2 SHAP：特征重要性解释

### 5.3 注意力可视化（NLP）

```python
"""可视化 Transformer 的注意力权重"""
from transformers import BertTokenizer, BertModel
import torch
import matplotlib.pyplot as plt

tokenizer = BertTokenizer.from_pretrained('bert-base-chinese')
model = BertModel.from_pretrained('bert-base-chinese', output_attentions=True)

text = "这只猫非常可爱"
inputs = tokenizer(text, return_tensors='pt')
outputs = model(**inputs)

# 获取注意力权重
attentions = outputs.attentions  # tuple of (batch, heads, seq, seq)

# 可视化最后一层的注意力
last_layer_attn = attentions[-1][0].mean(dim=0)  # 平均所有头
tokens = tokenizer.tokenize(text)

plt.figure(figsize=(8, 6))
plt.imshow(last_layer_attn.detach().numpy(), cmap='Blues')
plt.xticks(range(len(tokens)+2), ['[CLS]'] + tokens + ['[SEP]'], rotation=45)
plt.yticks(range(len(tokens)+2), ['[CLS]'] + tokens + ['[SEP]'])
plt.title('Attention Weights (Last Layer)')
plt.colorbar()
plt.tight_layout()
plt.show()
```

### 5.4 LIME：局部解释

```python
import lime
from lime.lime_text import LimeTextExplainer

explainer = LimeTextExplainer(class_names=['负面', '正面'])

def predict_fn(texts):
    """模型预测函数"""
    inputs = tokenizer(texts, padding=True, return_tensors='pt')
    with torch.no_grad():
        probs = torch.softmax(model(**inputs).logits, dim=-1)
    return probs.numpy()

# 解释单个预测
exp = explainer.explain_instance(
    "这部电影剧情很好，但演员表演一般",
    predict_fn,
    num_features=6,
)
exp.show_in_notebook()
# → 高亮显示哪些词对"正面/负面"判断贡献最大
```

### 6.1 全球 AI 监管格局

| 地区 | 法规 | 核心要求 |
|------|------|----------|

### 6.2 中国 AI 合规要点

```
《生成式人工智能服务管理暂行办法》(2023.8)：
1. 训练数据合法性：不使用侵权数据
2. 内容安全：不生成违法有害信息
3. 标识义务：AI 生成内容需标注
4. 用户权益：提供投诉渠道、不歧视
5. 安全评估：上线前进行安全评估和算法备案
```

### 6.3 负责任的 AI 开发清单

```markdown
□ 数据审计：训练数据来源合法、无严重偏见
□ 安全测试：通过 Red Team 测试
□ 公平评估：各群体性能差异 < 阈值
□ 隐私保护：数据脱敏、最小化收集
□ 透明告知：用户知道在与 AI 交互
□ 人类兜底：关键决策有人工审核
□ 监控告警：上线后持续监控
□ 回滚机制：发现问题能快速回退
□ 文档记录：模型卡 (Model Card) 完整
□ 合规审查：符合当地法规要求
```

## 八、本讲小结

| 议题 | 核心要点 | 工程师能做什么 |
|------|----------|---------------|
| 对齐 | 让 AI 行为符合人类意图 | RLHF/DPO、安全微调 |
| 偏见 | 数据/模型/输出中的不公平 | 分组评估、去偏技术 |
| 隐私 | 保护个人数据 | 差分隐私、本地推理、脱敏 |
| 可解释 | 理解模型为什么这样预测 | SHAP、LIME、注意力可视化 |
| 安全 | 防止滥用和攻击 | Red Team、输入过滤、输出验证 |
| 治理 | 合规、透明、负责 | Model Card、安全评估、人工兜底 |

**核心原则：** 技术能力越大，责任越大。作为 AI 工程师，你写的每一行代码都可能影响 millions 的人。
