9.1 LLM 的局限——为什么需要 RAG？

三个核心问题

问题表现例子
知识截止不知道训练数据之后发生的事"2026年最新的政策是什么？" → 答不出
幻觉编造不存在的事实编造论文引用、虚构法律条文
无私有数据不知道你的公司/个人信息"我们公司的报销流程是什么？" → 不知道

RAG 的解决思路

📌 RAG = Retrieval-Augmented Generation（检索增强生成）

核心思想：先检索相关文档，再让 LLM 基于文档回答。

纯 LLM：问题 → LLM → 回答（可能编造）
RAG：问题 → 检索相关文档 → [问题+文档] → LLM → 回答（有据可查）

类比：开卷考试 vs 闭卷考试。RAG 让 AI "开卷"回答。

9.2 Embedding——把文本变成向量

回顾第1章

第1章我们学了：向量可以表示"含义"，余弦相似度衡量"相似程度"。

Embedding 模型就是把一段文字变成一个向量（如 768 维或 1536 维），使得含义相近的文字向量也相近。

✏️ 例题 9.1：Embedding 的效果
from openai import OpenAI
client = OpenAI()

def get_embedding(text):
    resp = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return resp.data[0].embedding

# 获取向量
v1 = get_embedding("如何申请年假？")
v2 = get_embedding("请假流程是什么？")
v3 = get_embedding("今天天气怎么样？")

# 计算余弦相似度
import numpy as np
def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

print(cosine_sim(v1, v2))  # ≈ 0.92（很相似！）
print(cosine_sim(v1, v3))  # ≈ 0.25（不相关）

"申请年假"和"请假流程"含义相近 → 向量接近 → 余弦相似度高。

📌 Embedding 的关键认知
  • Embedding 把语义编码到向量空间中
  • 含义相近 → 向量距离近 → 余弦相似度高
  • 这是 RAG 的基础：用向量相似度找到"语义相关"的文档
  • 常用模型：OpenAI text-embedding-3、BGE、Jina
🌉 直觉桥梁：连接第1章

RAG 的检索步骤就是第1章学的余弦相似度！

把问题和文档都变成向量（Embedding），然后用余弦相似度找最接近的文档。

你在第1章学的"点积衡量相似度"，在这里直接变成了"搜索最相关的文档"。

从向量点积到 AI 搜索引擎，核心数学完全一样。

9.3 向量检索——找到最相关的文档

暴力搜索 vs 向量数据库

如果只有 100 个文档，可以逐个计算余弦相似度。但如果有 100 万个文档呢？

向量数据库（如 FAISS、Chroma、Milvus）使用近似最近邻（ANN）算法，在百万级向量中毫秒级找到最相似的 Top-K。

# 用 Chroma（最简单的向量数据库）
import chromadb

# 创建客户端和集合
client = chromadb.Client()
collection = client.create_collection("my_docs")

# 添加文档（Chroma 自动计算 embedding）
collection.add(
    documents=["公司年假为15天", "报销需提交发票", "上班时间9:00-18:00"],
    ids=["doc1", "doc2", "doc3"],
    metadatas=[{"source": "员工手册"}] * 3
)

# 查询：找到最相关的文档
results = collection.query(
    query_texts=["我想请假"],
    n_results=2
)
print(results['documents'])
# [['公司年假为15天', '报销需提交发票']]  ← 最相关的是年假文档

9.5 文档分块——Chunking 策略

为什么要分块？

一个 PDF 可能有 5 万字。不能把整本书塞给 LLM（太长、不相关、浪费 token）。

需要把文档切成小块（chunk），只检索最相关的几块。

分块策略

策略做法适用场景
固定大小每 500 字切一块通用（最简单）
按段落按 \n\n 切分结构化文档
递归分割先按大分隔符，再按小的最常用
语义分块按语义相似度变化点切高质量需求
📌 分块的关键参数
  • chunk_size：每块多大？通常 300-1000 字符
  • chunk_overlap：块之间重叠多少？通常 50-200 字符（防止切断语义）
  • 太大：检索不精确，包含无关信息
  • 太小：丢失上下文，语义不完整
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", "！", "？", " ", ""]
)

text = open("company_handbook.txt").read()
chunks = splitter.split_text(text)
print(f"文档被分成 {len(chunks)} 个块")
print(f"第1块: {chunks[0][:100]}...")

9.6 动手构建一个 RAG 问答系统

"""
完整 RAG 系统：从零构建（不依赖 LangChain）
"""
import numpy as np
from openai import OpenAI

client = OpenAI()

# ===== 1. 准备知识库 =====
documents = [
    "公司年假制度：入职满1年享5天年假，满5年享10天，满10年享15天。",
    "报销流程：填写报销单→附发票→部门经理审批→财务审核→3个工作日到账。",
    "工作时间：周一至周五 9:00-18:00，午休 12:00-13:30。",
    "加班规定：工作日加班1.5倍工资，周末2倍，法定节假日3倍。",
    "请假流程：提前在OA系统提交申请→直属领导审批→HR备案。",
]

# ===== 2. 计算所有文档的 Embedding =====
def get_embeddings(texts):
    resp = client.embeddings.create(
        model="text-embedding-3-small",
        input=texts
    )
    return [d.embedding for d in resp.data]

doc_embeddings = get_embeddings(documents)

# ===== 3. 检索函数 =====
def retrieve(query, top_k=2):
    """找到最相关的 top_k 个文档"""
    q_emb = get_embeddings([query])[0]
    
    # 计算余弦相似度
    similarities = []
    for doc_emb in doc_embeddings:
        sim = np.dot(q_emb, doc_emb) / (
            np.linalg.norm(q_emb) * np.linalg.norm(doc_emb)
        )
        similarities.append(sim)
    
    # 取 Top-K
    top_indices = np.argsort(similarities)[-top_k:][::-1]
    return [(documents[i], similarities[i]) for i in top_indices]

# ===== 4. 生成回答 =====
def rag_answer(question):
    # 检索
    results = retrieve(question, top_k=2)
    context = "\n\n".join([doc for doc, _ in results])
    
    # 构建 Prompt
    prompt = f"""基于以下参考资料回答问题。如果资料中没有相关信息，请说"根据现有资料无法回答"。

参考资料：
{context}

问题：{question}

回答："""
    
    # 调用 LLM
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
    )
    return response.choices[0].message.content

# ===== 5. 测试 =====
print(rag_answer("我工作了6年，有几天年假？"))
# → "根据公司制度，入职满5年享10天年假。您工作了6年，享有10天年假。"

print(rag_answer("怎么报销？"))
# → "报销流程：填写报销单→附发票→部门经理审批→财务审核→3个工作日到账。"

9.7 AI Agent——让 AI 使用工具

从"只能说"到"能做事"

普通 LLM 只能生成文字。Agent 让 LLM 能调用工具（搜索、计算、执行代码、操作数据库...）。

📌 Agent = LLM + 工具 + 规划
Agent 循环：思考 → 选择工具 → 执行 → 观察结果 → 继续思考 → ... → 最终回答

这就是 ReAct 模式（Reasoning + Acting）。

✏️ 例题 9.2：Agent 的工作过程
用户: "北京今天比上海热多少度？"

Agent 思考: 我需要查两个城市的天气
Agent 行动: get_weather("北京") → 结果: 32°C
Agent 思考: 还需要查上海
Agent 行动: get_weather("上海") → 结果: 28°C
Agent 思考: 32 - 28 = 4，可以回答了
Agent 回答: "北京今天32°C，上海28°C，北京比上海热4度。"

9.8 Function Calling 实战

"""OpenAI Function Calling 示例"""
import json
from openai import OpenAI

client = OpenAI()

# 定义工具
tools = [{
    "type": "function",
    "function": {
        "name": "calculate",
        "description": "计算数学表达式",
        "parameters": {
            "type": "object",
            "properties": {
                "expression": {
                    "type": "string",
                    "description": "要计算的数学表达式，如 '2+3*4'"
                }
            },
            "required": ["expression"]
        }
    }
}]

# 实际的工具实现
def calculate(expression: str) -> str:
    try:
        result = eval(expression)
        return str(result)
    except:
        return "计算错误"

# Agent 循环
def agent(question):
    messages = [{"role": "user", "content": question}]
    
    while True:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
        )
        msg = response.choices[0].message
        messages.append(msg)
        
        # 没有工具调用 → 返回最终回答
        if not msg.tool_calls:
            return msg.content
        
        # 执行工具
        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = calculate(**args)
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result,
            })

# 测试
print(agent("123乘以456再加789等于多少？"))
# → "123×456+789 = 56,877"

9.9 全栈 AI 应用架构

⚠️ 常见误区
✗ "RAG 让模型'学会'了新文档"
✓ RAG 不修改模型参数，只是在推理时提供参考文档。模型本身没变，只是"开卷考试"。文档更新后不需要重新训练模型。
✗ "Embedding 越长的模型越好"
✓ 维度要匹配需求。1536 维的 embedding 比 384 维的更精确，但存储和检索成本也更高。对大多数应用，384-768 维就够了。
✗ "Agent 就是更聪明的聊天机器人"
✓ Agent 的核心是'行动能力'。普通 LLM 只能生成文字，Agent 能调用工具（搜索、计算、执行代码）并根据结果调整策略。区别在于"能做事"而不只是"能说话"。
