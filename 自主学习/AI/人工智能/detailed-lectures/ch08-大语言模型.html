8.1 LLM 的本质：超级文字接龙

核心原理

不管 GPT-4 多强大，它的核心任务只有一个：

给定前面的文字，预测下一个最可能的词（token）
✏️ 例题 8.1：LLM 在做什么？

输入："今天天气真"

模型输出概率分布：

候选词概率
"好"0.45
"不错"0.20
"热"0.15
"冷"0.08
其他...0.12

模型选择"好"（概率最高），然后输入变成"今天天气真好"，继续预测下一个词...

就这样一个词一个词地生成，直到产生完整的回答。

📌 为什么"接龙"能产生智能？

当模型在万亿级文本上训练后，为了准确预测下一个词，它必须"理解"：

  • 语法结构（预测下一个词需要知道句子结构）
  • 事实知识（"中国的首都是___" → 必须知道是北京）
  • 逻辑推理（"如果 A>B, B>C, 那么 A___C" → 必须会推理）
  • 代码逻辑（预测下一行代码需要理解程序语义）

预测下一个词 = 压缩人类知识。这就是 Scaling Laws 的魔力。

8.2 Tokenization：文字变数字

什么是 Token？

LLM 不直接处理文字，而是处理 token（词元）。Token 是文本的最小处理单位：

语言Token 示例
英文"Hello" → ["Hello"]；"unhappiness" → ["un", "happi", "ness"]
中文"人工智能" → ["人工", "智能"] 或 ["人", "工", "智", "能"]（取决于模型）
数字"12345" → ["123", "45"]

BPE（Byte Pair Encoding）

现代 LLM 使用的分词算法。核心思想：从字符开始，反复合并最频繁的相邻对。

✏️ 例题 8.2：BPE 合并过程

语料："low low low lowest"

初始：每个字符是独立 token：[l, o, w, ' ', l, o, w, ' ', ...]
统计最频繁的相邻对："lo" 出现 4 次 → 合并为 "lo"
再统计："low" 出现 3 次 → 合并为 "low"
继续直到达到目标词表大小（如 32000）
# 查看 tokenizer 如何切分
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("gpt2")
text = "Hello, world! 你好世界"
tokens = tok.tokenize(text)
print(tokens)  # ['Hello', ',', ' world', '!', ' 你', '好', '世', '界']

ids = tok.encode(text)
print(ids)     # [15496, 11, 995, 0, 3574, 244, 98, 224]

# 解码回来
print(tok.decode(ids))  # "Hello, world! 你好世界"
📌 实用知识
  • 英文大约 1 token ≈ 4 个字符 ≈ 0.75 个单词
  • 中文大约 1 个汉字 ≈ 1-2 个 token
  • API 按 token 计费（输入 + 输出）
  • 上下文窗口（如 128K token）决定了模型能"看到"多少文本

8.3 训练三阶段：预训练→SFT→对齐

各阶段详解

阶段数据量算力学到什么
预训练1-15 万亿 token数千 GPU × 数月语言、知识、推理能力
SFT1-10 万条指令对几十 GPU × 数小时对话格式、遵循指令
对齐 (DPO)1-5 万条偏好对几十 GPU × 数小时安全性、有用性

8.4 推理过程：逐词生成

👇 动画：LLM 一个 token 一个 token 地生成回答（就像打字一样）

📌 关键概念：上下文窗口

模型有最大输入长度（如 128K token）。超过这个长度，早期的内容会被"遗忘"。

这就是为什么：

  • 超长对话时模型会"忘记"开头说的话
  • RAG 需要把相关文档塞进上下文窗口
  • 长文本处理是一个活跃的研究方向

8.5 温度与采样：控制创造性

Temperature（温度）

温度控制输出的"随机程度"：

温度效果适用场景
T = 0总选概率最高的词（确定性）事实问答、代码生成
T = 0.7适度随机，平衡准确和多样通用对话（默认）
T = 1.5高度随机，更有创意创意写作、头脑风暴
✏️ 例题 8.4：温度的效果

原始概率：["好"=0.5, "不错"=0.3, "热"=0.15, "冷"=0.05]

T=0：总选"好"（贪心）
T=0.7：大概率选"好"，偶尔选"不错"
T=2.0：四个词都有较大机会被选中（更随机）

Top-p（核采样）

只从累积概率达到 p 的最小词集中采样。如 top_p=0.9：只考虑概率加起来达到 90% 的那些词。

8.6 Prompt Engineering：和 AI 说话的艺术

基本原则

📌 好 Prompt 的公式
好 Prompt = 角色 + 任务 + 约束 + 格式 + 示例
✏️ 例题 8.5：Prompt 对比

❌ 差的 Prompt：

"帮我写代码"

✅ 好的 Prompt：

你是一位资深 Python 工程师。请帮我写一个函数：

功能：读取 CSV 文件，计算每列的均值和标准差
输入：文件路径（字符串）
输出：字典 {列名: {"mean": 值, "std": 值}}
要求：
- 处理缺失值（跳过 NaN）
- 添加类型注解和 docstring
- 用 pandas 实现
- 代码简洁，不超过 20 行

区别：好的 Prompt 给了明确的角色、具体的需求、清晰的约束。

System Prompt（系统提示）

# 设定 AI 的行为边界
system_prompt = """你是一个专业的数据分析助手。

规则：
- 只回答数据分析相关问题
- 不确定的事情明确说"我不确定"
- 给出代码时附带解释
- 用中文回答"""

8.7 思维链 (CoT)：让 AI 一步步想

问题

直接问复杂问题，LLM 经常出错：

问：一个商店打八折后再减20元，原价200元最终多少钱？
答（直接）：140元 ← 可能对也可能错

解决：Chain-of-Thought

问：一个商店打八折后再减20元，原价200元最终多少钱？
     请一步步思考。

答（CoT）：
1. 原价：200元
2. 打八折：200 × 0.8 = 160元
3. 再减20元：160 - 20 = 140元
答案：140元 ✓
📌 CoT 为什么有效？

LLM 是逐词生成的。写出中间步骤 = 给后续推理提供"上下文"。

就像人做数学题：写出中间步骤比直接心算更不容易出错。

触发 CoT 的魔法词："让我们一步步思考"、"请解释你的推理过程"

其他高级 Prompt 技巧

技巧做法适用场景
Few-shot给 2-3 个示例格式化输出、分类任务
CoT"一步步思考"数学、逻辑推理
ReAct思考→行动→观察循环需要调用工具的 Agent
Self-consistency多次采样取多数答案提高推理准确率

8.8 微调与 LoRA：定制你自己的模型

为什么需要微调？

  • 通用模型不了解你的私有数据（公司文档、专业术语）
  • 需要特定的输出风格或格式
  • 需要领域专业知识（医疗、法律）

LoRA 的直觉

全量微调 7B 模型需要 ~60GB 显存。LoRA 的思想：

不修改原始权重 W，而是学习一个小的"增量" ΔW = B × A 其中 B 是 d×r，A 是 r×d，r 很小（如 16）

只训练 0.1% 的参数，单张消费级 GPU 就能微调 7B 模型！

# LoRA 微调示例（用 Hugging Face PEFT）
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=16,                    # 秩（越大表达力越强，但参数越多）
    lora_alpha=32,           # 缩放因子
    target_modules=["q_proj", "v_proj"],  # 对哪些层加 LoRA
    lora_dropout=0.05,
)

model = get_peft_model(base_model, lora_config)
model.print_trainable_parameters()
# trainable params: 4M || all params: 6.7B || trainable%: 0.06%

8.9 调用 LLM API（实战）

"""调用 OpenAI 兼容 API（也适用于 DeepSeek、Qwen 等）"""
from openai import OpenAI

client = OpenAI(
    api_key="your-api-key",
    base_url="https://api.openai.com/v1"  # 或其他兼容端点
)

# 基本对话
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "你是一个Python教师，用简单例子解释概念。"},
        {"role": "user", "content": "什么是列表推导式？"}
    ],
    temperature=0.7,
    max_tokens=500,
)
print(response.choices[0].message.content)

# 流式输出（逐字显示）
stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "写一首关于春天的诗"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
⚠️ 常见误区
✗ "LLM 真的'理解'了语言"
✓ LLM 是极其强大的统计模式匹配。它通过预测下一个词学会了语法、知识、推理的模式，但是否真正"理解"仍有争议。不要把它当作全知全能的专家。
✗ "参数越多越聪明"
✓ 数据质量和训练方法同样重要。一个用高质量数据训练的 7B 模型，可能比用低质量数据训练的 70B 模型表现更好。Chinchilla 定律：参数和数据要等比例增长。
✗ "Prompt Engineering 就是'念咒语'"
✓ Prompt 设计是系统化的输入工程。好的 Prompt 有明确的角色、任务、约束、格式。它不是玄学，而是理解模型工作原理后的工程实践。

8.10 本章习题

📝 概念理解题
  1. LLM 的核心任务是什么？（一句话）
  2. 预训练和 SFT 的区别是什么？各自学什么？
  3. Temperature=0 和 Temperature=1 的输出有什么区别？
  4. 什么是 Token？为什么 API 按 token 计费而不是按字？
  5. LoRA 为什么能大幅减少微调的显存需求？
参考答案
  1. 给定前文，预测下一个最可能的 token。
  2. 预训练：海量文本，学语言知识和世界知识；SFT：指令-回答对，学会遵循指令和对话格式。
  3. T=0 总选概率最高的词（确定性、可能重复）；T=1 按原始概率采样（更多样、更有创意）。
  4. Token 是模型处理文本的最小单位（子词级别）。不同语言/文本的 token 密度不同，按 token 计费更公平。
  5. LoRA 不修改原始权重，只训练一个低秩增量（r=16 vs d=4096），可训练参数减少 99%+。
📝 实践题
  1. 用 LLM API 完成：(a) 翻译一段英文 (b) 总结一篇文章 (c) 写一个 Python 函数。对比不同 Prompt 的效果。
  2. 设计一个 System Prompt，让 AI 扮演"苏格拉底式教师"（不直接给答案，而是通过提问引导学生思考）。
  3. 用 CoT 技巧让 LLM 解决：一个水池有两个进水管和一个出水管，进水管A每小时注入3吨，B每小时注入2吨，出水管每小时排出1.5吨，水池容量50吨，从空到满需要几小时？
  4. 挑战：用 Hugging Face 的 transformers 库加载 GPT-2，手动实现逐词生成（不用 generate()），理解推理过程。
参考答案（题8）
from transformers import GPT2LMHeadModel, GPT2Tokenizer
import torch

tok = GPT2Tokenizer.from_pretrained("gpt2")
model = GPT2LMHeadModel.from_pretrained("gpt2")

prompt = "The future of AI is"
input_ids = tok.encode(prompt, return_tensors="pt")

# 逐词生成
for _ in range(20):
    with torch.no_grad():
        outputs = model(input_ids)
    next_token_logits = outputs.logits[:, -1, :]
    next_token = torch.argmax(next_token_logits, dim=-1)
    input_ids = torch.cat([input_ids, next_token.unsqueeze(0)], dim=-1)
    if next_token.item() == tok.eos_token_id:
        break

print(tok.decode(input_ids[0]))
