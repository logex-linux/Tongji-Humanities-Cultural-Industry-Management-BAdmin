## 从特殊情形到任意正幂

证明 log n < n，只证明了一个特殊上界，不能据此略去任意正幂的论证。现在给出完整版本。对任意 ε>0，令 q=2^ε>1。令 a_m=(m+1)/q^m。选定一个常数 r，使 1/q<r<1。因为 1/(m+1) 趋于0，可以找到固定 M，使所有 m≥M 满足

\[
\frac{a_{m+1}}{a_m}=\frac{1+1/(m+1)}q\le r.
\]

因此对每个 k≥0，反复使用同一不等式得到 a_(M+k)≤a_M r^k；右侧趋于0，故 a_m 趋于0。这里 M 和 r 先固定，不随待验证的 n 改变。

对 n≥1，取 m=⌊log₂n⌋，则 2^m≤n<2^(m+1)，于是

\[
0\le\frac{\log_2 n}{n^\varepsilon}\le\frac{m+1}{2^{m\varepsilon}}=a_m\longrightarrow0.
\]

所以 log n=o(n^ε)，并且 log n=O(n^ε)。换对数底只引入常数。这个证明比“把 n 换成另一个幂，所以同理成立”多给出了关键的量词和极限步骤。

## 操作计数与机器计时分别回答什么

一层循环中执行 `total += i`，即使 total 的最终数值是平方量级，循环次数仍为线性。**结果的数量级不等于工作次数。** 同理，循环内执行一次 `steps += n`，不能宣称真的执行了 n 次操作。

配套实验明确执行每次被计数的工作。n=128、256、512 时，一层循环分别计数128、256、512；两个完整嵌套循环分别计数16384、65536、262144。相关循环 `j=i; j*=2` 的计数则为255、511、1023。后者来自逐项执行，也符合 n 为2的幂时的公式 2n−1。

这些是精确操作数，没有捏造秒数。若增加机器计时，必须记录 Python 版本、硬件、输入、预热和重复方法；不得以三点计时证明渐近复杂度。

## 一次正确的最大流验收

先验证每条边的流量在容量范围内、内部节点流守恒，并计算流值。再给出包含 s、不含 t 的顶点集合 S，累加从 S 到其补集的有向边容量。弱对偶告诉我们任意可行流值都不超过任意合法割容量；若二者相等，可行流就是最大流，割就是最小割。证明依赖可行性和割的合法性，**不再要求另找一个算法证明同一最优值**。
